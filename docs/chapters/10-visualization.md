# 算法可视化

算法可视化把抽象的执行过程变成肉眼可见的动画。它是教学中最有效的工具——一个好的可视化能省去 10 页文字解释。本章梳理可视化的设计原则、常见模式与实现技巧。

## 1. 为什么需要可视化

- **直观理解**：数组、链表、树的结构在动画下一目了然
- **逐步教学**：单步播放让学生看到"每一步发生了什么"
- **调试辅助**：算法行为不符合预期时，可视化能快速定位问题
- **吸引兴趣**：比纯文字更能保持学习者专注

## 2. 可视化的核心元素

### 2.1 数据模型

每个可视化都基于**领域数据**：

- **数组**：柱状图，柱高 = 值大小
- **链表**：节点 + 箭头，可展示指针变化
- **树**：节点 + 父子连线，按层布局
- **图**：顶点 + 边，可加权重标签
- **哈希表**：桶 + 链表/红黑树

### 2.2 步骤生成

把算法执行过程切分为**离散的步骤（frames）**：

```javascript
// 冒泡排序的步骤生成
function bubbleSortSteps(input) {
  const arr = input.slice()
  const steps = [{ array: arr.slice(), compare: [], swap: [], sorted: [] }]
  // ... 每一步 push 一个 frame
  return steps
}
```

每个 frame 包含：

- 当前数据快照（`array` / `tree` / `nodes`）
- 关键状态（`compare` / `swap` / `visited` / `current`）
- 元信息（步号、动作类型）

### 2.3 动画控件

四个核心控件缺一不可：

| 控件 | 作用 |
|------|------|
| 上一步 | 回退一帧 |
| 下一步 | 前进一帧 |
| 播放 / 暂停 | 自动循环 |
| 重置 | 回到初始 |

## 3. 视觉编码

用**颜色**传递状态：

| 颜色 | 状态 |
|------|------|
| 灰色 | 初始 / 未访问 |
| 黄色 | 当前正在处理 |
| 红色 | 交换 / 删除 |
| 蓝色 | 候选 / 区间内 |
| 紫色 | 特殊（如 pivot） |
| 绿色 | 已完成 / 已排序 |

**形状**也传递信息：

- 圆角矩形：数组元素
- 圆形：链表节点 / 树节点
- 箭头：指针、父子关系
- 虚线：理论位置（如 null 子节点）

## 4. 布局算法

### 4.1 数组布局

最简单的等宽柱状图，柱高按值映射：

```javascript
const max = Math.max(...arr, 1)
const barWidth = 100 / arr.length
arr.map((v, i) => {
  const h = (v / max) * (height - 30)
  return `<div style="width: ${barWidth}%; height: ${h}px" />`
})
```

### 4.2 树布局

**分层定位**：第 d 层 y = d × 60，x 在 [left, right] 区间内插值：

```javascript
function layout(node, depth, left, right, out = []) {
  if (!node) return null
  const x = (left + right) / 2
  const y = 40 + depth * 60
  const pos = { val: node.val, x, y }
  out.push(pos)
  layout(node.left, depth + 1, left, x, out)
  layout(node.right, depth + 1, x, right, out)
  return pos
}
```

### 4.3 图布局

| 算法 | 适用 |
|------|------|
| 力导向 | 通用，呈现社区结构 |
| 圆形 | 展示环、对称性 |
| 网格 | 时间/空间分片 |
| 层次（DAG） | 任务依赖、调度 |

## 5. 动画策略

### 5.1 过渡时间

- **100-300ms**：适合频繁的步骤切换
- **400-700ms**：适合"重操作"（节点插入、指针重连）
- **≥ 1000ms**：适合"关键节点"（找到目标、排序完成）

### 5.2 缓动函数

避免线性动画的"机械感"：

- **ease-in-out**：平滑启动和停止
- **ease-out**：开始快、结束慢（适合"出现"动画）
- **ease-in**：开始慢、结束快（适合"消失"动画）

### 5.3 状态叠加

当多状态并存时（如"已访问" + "当前"），优先级：

1. 当前（黄） > 交换/删除（红） > 比较（黄） > 已访问（绿） > 默认

## 6. 常见模式的实现

### 6.1 排序可视化

- **冒泡**：相邻比较，红色高亮交换
- **快速**：紫色 pivot，黄色比较，绿色已分区
- **归并**：左右子数组用不同颜色，合并时用动画连接

### 6.2 搜索可视化

- **二分**：蓝色高亮 `[lo, hi]` 区间，黄色标记 `mid`
- **BFS**：用波纹动画逐层扩散

### 6.3 树遍历

- **DFS**：访问节点 + 递归进入子树用不同颜色
- **BFS**：按层级波次，每层一个颜色

### 6.4 链表操作

- **插入**：先建新节点，箭头动画连接
- **删除**：箭头先断开，节点再淡出
- **反转**：逐步重新连接 next 指针

## 7. 性能与可访问性

### 7.1 性能

- **避免全量重绘**：只重绘变化的部分
- **requestAnimationFrame**：动画用 raf 而非 setTimeout
- **节流（throttling）**：高频更新时限制帧率
- **虚拟化**：大数据集只渲染可见部分

### 7.2 可访问性

- **键盘控制**：方向键切换步骤、空格播放/暂停
- **ARIA 标签**：每个按钮有 `aria-label`
- **颜色对比**：满足 WCAG AA（4.5:1）
- **替代文本**：颜色不应该是唯一的状态指示（加文字 / 图标）

## 8. 框架选型

| 场景 | 选型 |
|------|------|
| 简单柱状 / 链表 | 原生 DOM + CSS |
| 树 / 图 | SVG |
| 复杂图（万级节点） | Canvas + d3-force |
| 大量数据流 | WebGL（PixiJS、Three.js） |
| 数据看板 | AntV G2 / ECharts |

本学习平台的 P1 阶段使用**原生 React + SVG + CSS 过渡**实现排序、二分、链表、树四种基础可视化，零外部依赖、易于理解。

## 9. 教学节奏

可视化最好配合**解说**：

1. **运行前**：说明算法目标、初始状态
2. **每步**：用一句简短的话解释"现在发生了什么"
3. **运行后**：总结复杂度、关键技巧

例（冒泡排序）：

- 步骤 1：比较 a[0]=5 和 a[1]=3，5>3，交换 → 黄色 → 红色
- 步骤 2：比较 a[1]=5 和 a[2]=8，5<8，不交换
- ……

## 10. 验证清单

一个合格的可视化应满足：

- [ ] 至少 4 个控件（上一步/下一步/播放/重置）
- [ ] 颜色编码与文字标签双重传达状态
- [ ] 在慢速（≥ 1s/步）和快速（≤ 100ms/步）下都正常
- [ ] 边界情况（空数组、单个元素、已排序）不崩溃
- [ ] 切换算法时状态正确重置
- [ ] 移动端可操作（按钮足够大，文字不溢出）

## 11. 扩展方向

- **DSL 描述**：用配置语言描述可视化（类似 mermaid）
- **录制 / 回放**：保存用户操作序列
- **协作模式**：多人同步观看同一可视化
- **3D 可视化**：复杂图用 z 轴表示额外维度

## 12. 小结

可视化不是"画得漂亮"就够了，关键是**准确传达算法行为**。优先用**清晰的视觉编码**（颜色 + 形状 + 文字），其次才是动画效果。一个简单的、对学生友好的可视化，比一个炫酷但不清晰的版本价值大得多。
